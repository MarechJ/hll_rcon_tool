Quick start

Using the API

Replace crcon.example.com with the host and port of your CRCON installation. All routes are available below the /api/ prefix.

01

Try a public endpoint

get_public_info returns the current map, player counts, score, match time, vote status, and server identity without requiring a login.

The other public routes are get_version, get_api_documentation, is_logged_in, login, and logout. A reverse proxy may still restrict them.

Open endpoint reference →
Public request · cURL
curl "https://crcon.example.com/api/get_public_info" \
  -H "Accept: application/json"
02

Authenticate

All other endpoints require a CRCON user and that user's permissions. Choose a session cookie for interactive tools or a bearer token for unattended clients.

Session cookie

Log in through /api/login

POST a username and password, then reuse the returned sessionid cookie on later requests to the same CRCON host.

  • Postman and Insomnia retain it in their cookie jars automatically.
  • In cURL, use -c to save the cookie and -b to send it.
  • In Python, use one requests.Session; in browser code, set credentials: "include".
cURL session
curl -c crcon.cookies \
  -X POST "https://crcon.example.com/api/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"PASSWORD"}'

curl -b crcon.cookies \
  "https://crcon.example.com/api/get_gamestate"

Bearer token

Generate a token from /accounts

A CRCON administrator generates the token for a user from the Accounts page. The token acts with that user's permissions.

  • Best suited to bots, monitoring, scheduled scripts, and CI jobs.
  • Treat it like a password and store it in a secret manager or environment variable.
  • Send it as Authorization: Bearer TOKEN on every request.
Bearer request
curl "https://crcon.example.com/api/get_gamestate" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Accept: application/json"
